Task 1: Drawing Single-Color Triangles

To rasterize each triangle we test whether the center of the pixel lies inside it. It first checks that the framebuffer has nonzero dimensions and does not try to rasterize triangles with zero areas.

Then we computed the triangles bounding box using the minimum and maximum x and y cordinates of its three vertices. Once we have those coordinates, we iterate through each pixel in the bounding box and test if it lies inside the triangle. Those points were turned into candidate pixel indices because the pixel (x, y) is samples at ( x + 1/2, y + 1/2), the horizontal candidate range starts at ceil(min_x - 1/2) and ends at floor(max_X -0.5). Then we calculate the vertical range in the same way and clip both ranges to the framebuffer boundaries. For each of those candidate pixels we evaluate three edge functions at its center. For a directed edge from A to B and sample point P, the helper edge function is: E(A, B, P) = (B.x - A.x) * (P.y - A.y) - (B.y - A.y) * (P.x - A.x). The sign indicates which side of the edges line containes the sample.

The edges are calculated in order from V0 -> V1, V1 -> V2, and V2 -> V0. A sample is accepted if all three edge values are nonnegative or all three are nonpositive. This is because both sign patterns allow the implementation to reasterize triangles with either clockwise or counterclockwise vertex orders. This also allows for samples that lie on the triangles boundary to be drawn. When a sample is then accepted, we call fill_pixel(x, y, color) using the integer pixel indices. Every accepted pixel recieves the same triangle color and this implementation uses one sample per pixel and includes all triangle edges instead of implementing the optional top-left edge rule.

Our implementation only tests pixel centers within the triangles bounding box, clipped to the framebuffer but it does not scan pixels elsewhere in the image. If the candidate region contains(B_w) columns and (B_h) rows the nested loop performs (B_wB_h) sample tests. Each test uses three edge function evaluations and a constant number of comparisons so the running time is (O(B_wB_h)). This meets the requirement that the algorithmn be no worse than checking every sample within the bounding box.

Task 2: Antialiasing by Supersampling

Each pixel is sampled using a sqrt(N) * sqrt(N) grid of subcell centers with N being the sample_rate. Within each of the triangles bounding box, we test three edge cases to every sample and store covered samples colors in sample_buffer. This vector holds width * height * N floating point colors, grouped by pixel.

We resize the buffer when the sample_rate or framebuffer dimensions change and clear it before each redraw. I updated fill_pixel() to fill all samples of a pixel for points and lines. Then after rendering the resolve_to_framebuffer() averages each pixel's samples and converts the results.

Supersampling estimates partial coverage which creates the intermediate boundary colors that reduce jagged edges. Rate 1 gives binary coverage, rate 4 and 16 estimate coverage in incriments of 1/4 and 1/16 which should produce progresively smoother edges.

Task 4: Barycentric coordinates

Barycentric coordinates describe a point as a weighted comnbination of a triangles three vertices. The weights sum to one and are nonnegative inside the triangle. At their vertex the weight is one and the other two are zero. At the centroid each weight is one-third. We calculate these weights by dividing each opposite edge function value by the triangles signed double area. Task 5: "Pixel sampling" for texture mapping

Pixel sampling is how we choose a color from a texture for each sample that lands inside a textured triangle. For every covered subpixel, we first calculate its barycentric coordinates. We use those weights to interpolate the triangle's u and v texture coordinates, and then sample from level zero of the texture, which is the full-resolution image.

For nearest sampling, we map the u and v coordinates to texel coordinates, round to the closest texel, clamp the result to the texture boundaries, and use that texel's color. This is simple and fast, but it can create blocky changes because the color jumps as soon as a different texel becomes the closest one. For bilinear sampling, we find the four texels surrounding the sample point. We blend the top and bottom pairs using the horizontal fraction, then blend those two results using the vertical fraction. This gives us a smoother color between texels instead of immediately snapping to one texel.

Nearest and bilinear comparison

We used the pixel inspector on the Campanile windows because the dark windows, light walls, and thin horizontal ledges make the sampling differences easier to see.

Nearest sampling at one sample per pixel has the most noticeable blocky and uneven transitions around the windows and ledges. Raising the sample rate to 16 makes the triangle edges and small features smoother because the final pixel averages several subpixel results, but nearest sampling still chooses only one texel for each subpixel. Bilinear sampling gives smoother changes between the light stone and dark windows because it blends nearby texels. The combination of bilinear sampling and 16 samples per pixel gives the smoothest result overall.

The difference between nearest and bilinear sampling is largest in areas with fine details or strong color contrast, especially when a screen sample falls between texel centers. It also becomes more noticeable when a texture is stretched, rotated, or made smaller on the screen. Nearest sampling can skip back and forth between texels in those cases, while bilinear sampling blends the nearby values and makes the change less harsh.

Task 6: "Level Sampling" with mipmaps for texture mapping

Level sampling means choosing which mipmap level to sample instead of always using the full-resolution texture. A mipmap stores smaller versions of the same image. When a texture gets small on the screen, using one of those smaller levels gives each screen sample a color that already represents a larger area of the original texture. This helps stop tiny details from turning into noisy or flickering patterns.

To choose a level, we interpolate the texture coordinates at the current sample, one screen pixel to the right, and one screen pixel up. We subtract the current uv value from the other two to see how quickly the texture coordinates are changing across the screen. After scaling those changes by the full texture width and height, we take the larger length and use its base-2 logarithm as the mipmap level. Small changes stay close to level zero, while bigger changes use a smaller version of the texture.

For L_ZERO, we always sample level zero. For L_NEAREST, we round the calculated level and sample the closest mipmap. For L_LINEAR, we keep the level as a decimal, sample the two levels around it, and blend the results. Pixel sampling still works independently, so each chosen level can use either nearest or bilinear pixel sampling. Using L_LINEAR together with bilinear pixel sampling gives trilinear filtering.

Sampling tradeoffs

Nearest pixel sampling is the fastest because it reads one texel, but it can look blocky. Bilinear pixel sampling reads four texels and blends them, so it costs a little more time but gives smoother results when a sample lands between texels. It does not need extra texture levels, though, and by itself it cannot fully fix aliasing when a large part of a texture gets squeezed into a small number of pixels.

Level sampling is especially useful when the texture is being made smaller. Nearest level sampling adds the cost of calculating a mip level but still samples only one level. Linear level sampling samples two mip levels and blends them, so it is slower but avoids a sudden change when the selected level switches. Mipmaps also use extra memory because all of the smaller texture copies have to be stored. Supersampling works more generally on triangle edges and textures, but it needs a larger sample buffer and repeats the rasterization and texture work several times per pixel. This makes it the most expensive option as the sample rate goes up.

Level and pixel sampling comparison

For this comparison, we used a public-domain Moiré pattern from Wikimedia Commons. The close lines make aliasing easy to see. We kept the view, sample rate, and pixel inspector location the same in all four screenshots.

The two level-zero images keep every line from the full-resolution texture, so the center turns into a very noisy pattern when those lines become smaller than a screen pixel. Bilinear pixel sampling softens the individual blocks in the inspector, but it does not remove most of that noise because it is still reading from level zero. With nearest level sampling, the center becomes much calmer because a smaller mipmap level averages the details before they reach the screen. Adding bilinear pixel sampling makes the transitions between nearby texels less harsh, so L_NEAREST with P_LINEAR looks the smoothest out of these four required combinations.
